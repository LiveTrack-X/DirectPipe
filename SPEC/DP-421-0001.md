# DirectPipe v4.2.1 Reliability Hardening

Status: Software verified
Baseline: SPEC/SPEC-COMPLETE.md
Baseline revision: 948bce1 plus the preserved owner recording worktree patch
Effective packet: DP-421-0001
Supersedes:
- None (additive)

## Objective

Close the verified v4.2.1 audio, recording, persistence, IPC, control-state,
updater, and release-pipeline defects found by the repository-wide audit while
preserving the public IPC, VST Receiver, HTTP/WebSocket, and Stream Deck
compatibility contracts of the v4.2.x lane.

## Authorized Scope

- Correct built-in noise-removal buffering, fixed latency, large-block safety,
  and non-48 kHz latency reporting.
- Force a real same-device Windows Audio reopen after external endpoint changes,
  re-resolve recreated endpoint IDs, and validate the fallback stream when a
  saved ASIO device cannot be restored.
- Serialize recorder start/stop publication, count only accepted writer blocks,
  generate collision-free filenames, and keep playback selection scoped to the
  selected recording folder.
- Serialize VST graph lifecycle and structural mutations without adding a lock
  to the real-time process path.
- Make reset, clear, autosave, slot switch/copy/export/import, slot-name,
  hotkey/MIDI, settings import, backup/restore, and deletion failure handling
  explicit and recoverable.
- Prevent stale asynchronous loads and UI callbacks from restoring cleared
  state or dereferencing destroyed components.
- Make Receiver reconnect and latency notification safe, recover from POSIX
  producer generations, and publish the active preset through the control API.
- Make Windows in-app updater integrity verification for v4.2.0-and-later
  releases require an exact readable checksum entry and matching SHA-256, and
  make update/API errors diagnosable without weakening the documented
  loopback-only boundary. Manual browser downloads remain outside this check.
- Make the CI release workflow build and validate artifacts before publishing a
  GitHub Release, and fail when required compatibility SDK inputs are absent.
- Align version 4.2.1, changelog, test-count wording, and current documentation.

## Compatibility Boundary

- The shared-memory wire ABI remains protocol v1 with existing field offsets
  and the 192-byte header unchanged; `producer_generation` uses previously
  reserved bytes. Receiver plug-in identity, action names, HTTP/WebSocket
  payload shapes, and Stream Deck action UUID/request payloads remain compatible.
- Older Receivers remain ABI-compatible but do not gain the v4.2.1
  reconnect/lifecycle fixes. A stopped older Receiver that retains the Windows
  mapping can temporarily prevent a fresh producer from starting IPC; the host
  must fail closed rather than overwrite an in-use mapping.
- Same-sample-rate operation between DirectPipe and Receiver remains the v4.2.x
  contract; adding a real-time resampler is not required by this bug-fix packet.
- Mandatory authentication or a separately hosted VST sandbox would be a
  material compatibility/architecture change. Apply compatible hardening where
  possible and retain any remaining limitation as an explicit finding.
- No commit, push, tag, package publication, GitHub Release, or deployment is
  authorized by this packet.

## Acceptance Criteria

1. Noise removal emits exactly its declared fixed latency for supported sample
   rates and does not overwrite queued samples at callback sizes through 4096.
2. Recorder start/stop/device teardown cannot publish a recording state without
   a writer; dropped blocks do not inflate duration; rapid restarts use distinct
   files; folder changes do not restore a recording from a previous folder.
3. VST graph prepare/release/add/remove/replace operations share one control
   synchronization boundary while audio processing remains non-blocking.
4. A Windows Audio endpoint restart recreates the current device even when its
   JUCE setup is unchanged; a target recreated under a new endpoint ID is
   re-resolved; failed ASIO restoration retries 2-in/2-out, 1-in/2-out, then
   1-in/1-out and never reports an invalid fallback stream as ready.
5. Reset and clear invalidate pending loads, always leave loading state, reset
   the live recording folder, and report partial filesystem failures.
6. Persistence operations preserve dirty state on failure, abort destructive
   transitions, and make active-slot import transactional.
7. Full backup restores recording configuration, settings import reports
   failures/partial restores, and UI asynchronous callbacks are lifetime-safe.
8. Receiver reconnects after producer replacement without filesystem work or
   host latency notification from the audio callback; API preset state is
   populated.
9. Windows in-app updater downloads for v4.2.0 and later require an exact
   readable `checksums.sha256` entry and matching SHA-256; missing, unreadable,
   or mismatched metadata fails closed, manual browser downloads remain outside
   this check, and update failures are distinguishable from "no update".
10. CI does not create a public release before validation/assets exist and does
   not advertise VST2/ASIO compatibility when the required SDK inputs are absent.
11. Focused regression tests, Release build, relevant CTest suites, text
    integrity, and patch hygiene pass on the integrated worktree.
12. Hardware, third-party VST crash containment, and published-artifact claims
    remain explicitly unverified until their separate evidence gates run.
